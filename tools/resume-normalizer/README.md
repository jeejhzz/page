# 이력서 표준화 도구

자유 양식으로 받은 이력서(PDF · Word · 텍스트)를 읽어 **A4 규격 표준 이력서**로 바꾼다.
사람마다 제각각인 편집을 하나의 틀로 맞춰, 여러 명을 나란히 놓고 볼 수 있게 하는 것이 목적이다.

```
자유 양식 이력서        →  텍스트 추출  →  항목 구조화  →  A4 표준 이력서(PDF/HTML) + 요약표(CSV)
 .pdf .docx .hwpx .hwp     레이아웃 복원     규칙 / Claude
```

쓰는 방법은 두 가지다. **웹 화면**에 파일을 끌어다 놓거나, **명령줄**로 폴더째 돌리거나.

## 설치

```bash
cd tools/resume-normalizer
npm install
```

PDF 출력에는 Playwright의 Chromium을 쓴다. 이미 설치돼 있으면 그대로 쓰고,
없으면 `npm i -D playwright && npx playwright install chromium` 한 번만 해두면 된다.

## 브라우저에서 바로 확인하기

설치 없이 눌러 보려면 데모 한 장을 만들어 브라우저로 열면 된다.

```bash
node web/build-demo.js out/demo.html      # 2.6MB 짜리 HTML 한 장
```

파싱 코어와 PDF·워드·한글 판독기를 전부 그 안에 넣어 두어서, 서버 없이 파일 하나로 돈다.
올린 파일은 브라우저 밖으로 나가지 않는다. 다만 데모라 **PDF 내려받기는 되지 않고** 미리보기와 인쇄까지만 된다.

## 웹으로 쓰기 (권장)

```bash
npm start            # http://127.0.0.1:7000
```

브라우저에서 열고 이력서를 끌어다 놓으면 된다. 여러 개를 한 번에 올려도 되고,
왼쪽 목록에서 사람을 고르면 오른쪽에 완성된 A4 이력서가 바로 보인다.

- **검토 필요** 항목은 노란 박스로 뜬다. 못 읽은 칸이 무엇인지 바로 알 수 있다.
- 오른쪽 **기본 정보 수정**에서 값을 고치고 `고쳐서 다시 만들기` 를 누르면 PDF가 다시 만들어진다.
  학력·경력처럼 구조가 있는 항목은 아래 **전체 데이터(JSON)** 를 펼쳐서 고친다.
- 개인별 `PDF` · `블라인드 PDF` · `JSON` 을 내려받거나, 위쪽에서 `요약표 CSV` · `전체 ZIP` 을 받는다.

옵션: `--port 7000` `--host 127.0.0.1` `--engine auto|llm|rules` `--work <임시폴더>`

기본은 **127.0.0.1** 에만 바인딩한다. 지원자 개인정보를 다루므로 `--host 0.0.0.0` 으로 외부에 열지 말 것.

## 명령줄로 쓰기

```bash
# 폴더 통째로
node src/cli.js ./받은이력서 -o ./결과

# 파일 몇 개만
node src/cli.js 홍길동.pdf 김철수.docx -o ./결과

# 블라인드 심사용 사본도 같이
node src/cli.js ./받은이력서 -o ./결과 --blind
```

결과 폴더에 지원자마다 이렇게 떨어진다.

| 파일 | 내용 |
|---|---|
| `{이름}.pdf` | A4 표준 이력서 |
| `{이름}.html` | 같은 내용의 웹 버전 (수정해서 다시 인쇄하기 좋다) |
| `{이름}.json` | 뽑아낸 항목 원본 데이터 |
| `{이름}_blind.pdf` | `--blind` 일 때. 이름·생년월일·성별·주소·연락처를 지운 사본 |
| `summary.csv` | 전원 한 줄 요약. 엑셀에서 바로 열린다 |

### 옵션

| 옵션 | 설명 |
|---|---|
| `-o, --out <dir>` | 결과 폴더 (기본 `out`) |
| `--engine auto\|llm\|rules` | 파싱 엔진. 기본 `auto` — API 키가 있으면 `llm`, 없으면 `rules` |
| `--model <name>` | LLM 모델 (기본 `claude-sonnet-5`) |
| `--blind` | 블라인드 사본을 함께 생성 |
| `--only-blind` | 블라인드 사본만 생성 |
| `--no-pdf` | PDF 없이 HTML/JSON만 |
| `--concurrency N` | 동시 처리 수 (기본 3) |

## 파싱 엔진 두 가지

**`rules`** — 정규식과 섹션 헤딩으로 읽는다. API 키도 네트워크도 필요 없다.
`학력` `경력` `수상` 같은 제목을 달고 기간이 앞에 오는, 흔한 형태에는 잘 맞는다.
반대로 경력을 줄글로 서술했거나 제목 없이 쭉 이어 쓴 이력서는 놓치는 항목이 생긴다.

**`llm`** — Claude에게 원문을 주고 정해진 스키마로 채우게 한다. 자유 양식일수록 차이가 크다.

```bash
export ANTHROPIC_API_KEY=sk-ant-...
node src/cli.js ./받은이력서 -o ./결과        # auto 라서 자동으로 llm 을 쓴다
```

없는 경력이나 없는 성과를 지어내지 않도록 시스템 프롬프트와 스키마 양쪽에서 못박아 뒀고,
모델이 확신하지 못한 부분은 `_meta.warnings` 에 남겨 사람이 확인하게 한다.
LLM 호출이 실패하면 자동으로 규칙 기반으로 내려간다(`--engine llm` 을 명시하면 그냥 실패시킨다).

## 읽어내는 항목

이름 · 영문이름 · 생년월일 · 성별 · 주소 · 연락처 · 이메일 · 링크 · 지원직무 · 요약 ·
학력 · 경력 · 프로젝트 · 수상 · 특허 · 논문 · 자격 · 어학 · 기술스택 · 병역

값은 전부 한 형태로 정규화한다. 연락처는 `010-1234-5678`, 날짜는 `2021.03`,
재직 중이면 종료일을 `현재` 로 둔다. 그래야 여러 사람 이력서에서 같은 자리를 눈으로 훑을 수 있다.

### 총 경력 계산

경력 기간에서 **총 경력**을 자동으로 계산해 머리 표와 요약표에 넣는다. 항목마다 재직 길이도
기간 아래에 적는다.

그냥 더하지 않는다. 같은 시기에 두 자리를 겸했거나, 이력서가 한 회사를 승진 단위로 쪼개 적었거나,
앞의 요약표와 뒤의 상세에 같은 경력을 두 번 썼으면 같은 기간을 두 번 세게 된다.
그래서 **구간을 겹치는 대로 합친 뒤 길이를 잰다.** 한 달 차이로 이어지는 이직
(2025.03 퇴사 → 2025.04 입사)은 끊긴 것으로 보지 않는다.

- 공백기가 있으면 그만큼 빠지고, 머리 표에 `N개 구간` 으로 표시된다.
- 시작이나 종료를 못 읽은 항목은 합산에서 빼고 `N건 제외` 로 알린다. 값을 채워 넣으면 즉시 다시 계산된다.
- 프로젝트는 대개 재직 기간 안에 들어가므로 합산에 넣지 않는다.
- 시작·종료가 똑같은 항목은 같은 자리로 보고 하나로 합친다(요약표 + 상세를 함께 쓴 이력서 대응).

## 검토가 필요한 지점

자동 변환은 완벽하지 않다. 아래 경우 `_meta.warnings` 에 기록되고,
HTML 화면에는 노란 박스로 뜬다(인쇄하면 나오지 않는다).

- 이름·연락처·이메일을 찾지 못함
- 학력이나 경력이 비어 있음
- 경력에 기간이 없음
- 원본에 주민등록번호로 보이는 값이 있음 → **표준 이력서에는 저장하지 않는다**

`summary.csv` 의 `검토필요` 열만 훑으면 손봐야 할 사람이 바로 보인다.

## 한계

- **내용이 이미지로 들어간 PDF는 못 읽는다.** 스캔본뿐 아니라 발표자료를 이미지로 내보낸 PDF도 해당한다.
  글머리표와 쪽번호만 텍스트로 남고 본문이 빠지므로, 추출된 **글자 수**(한글·영문·숫자)를 세어
  120자 미만이면 실패시킨다. OCR을 거치거나 원본 Word/텍스트를 받아야 한다.
- **한글 PDF는 CMap이 있어야 읽힌다.** pdfjs에 CJK CMap 경로를 넘기지 않으면 한글이 통째로 사라지고
  글머리표만 남아 "이미지 PDF"로 오인하게 된다. 함정이 하나 더 있는데, Node에서는 이 경로를
  **그냥 파일 경로**로 줘야 한다. `pathToFileURL` 로 만든 `file://` URL을 주면 조용히 실패한다
  (`src/extract.js` 의 `assetPaths`).
- **`.doc`(구버전 워드)는 지원하지 않는다.** `.docx` 나 PDF로 변환해서 넣어야 한다.
- **한글 파일은 `.hwpx` 가 안전하다.** HWPX는 ZIP+XML이라 문단·표를 그대로 읽는다.
  `.hwp`(바이너리)는 `hwp.js` 로 시도하지만 문서에 따라 실패할 수 있고, 그때는
  "HWPX나 PDF로 저장해서 넣어달라"는 메시지를 낸다. 한글에서 *다른 이름으로 저장 → HWPX* 하면 된다.
- 2단 편집 PDF는 세로 여백을 찾아 열을 나눠 읽는다. 표로 짠 이력서를 잘못 쪼개지 않도록
  좌우 행이 짝을 이루는 비율로 두 경우를 가른다(`src/extract.js` 의 `findGutter`).
  그래도 편집이 특이하면 순서가 섞일 수 있다.
- **모르는 제목의 구역**은 글자 크기로 알아본다. PDF는 본문 글자 크기의 1.18배 이상인 줄,
  워드는 제목 스타일을 제목으로 보고 거기서 구역을 끊는다. 다만 회사명도 큰 글씨로 쓰는 경우가 많아,
  열두 글자가 넘고 법인 표기(㈜, 주식회사 …)가 없을 때만 구역을 닫는다(`parse-rules.js` 의
  `looksLikeSectionTitle`). 짧은 제목의 문서 고유 구역은 여전히 앞 섹션에 딸려 들어갈 수 있다.
- 규칙 엔진은 어디까지나 오프라인 대비책이다. 실제 채용에는 `llm` 을 권한다.

## 개인정보

- 모든 처리는 로컬에서 일어난다. `rules` 엔진은 네트워크를 쓰지 않는다.
- `llm` 엔진은 이력서 원문을 Anthropic API로 보낸다. 지원자 개인정보가 외부로 나가는 것이므로,
  사내 개인정보 처리방침과 위탁 고지 범위를 먼저 확인할 것.
- 결과 폴더에는 개인정보가 그대로 들어 있다. 저장소에 커밋하지 말 것(`.gitignore` 에 `out/` 이 있다).
- 참고: 채용절차법과 남녀고용평등법상 성별·연령 등은 직무 수행에 필요한 경우가 아니면
  수집·요구가 제한된다. 서류 심사에는 `--blind` 로 만든 사본을 쓰는 편이 안전하다.

## 구조

```
src/
  server.js       로컬 웹 서버 (업로드 · 미리보기 · 수정 · 다운로드)
  extract.js      파일 → 평문. PDF 좌표로 줄·열 복원, DOCX 표를 탭으로, 큰 글씨는 제목으로 표시
  hwp.js          한글 파일. HWPX(ZIP+XML) 파싱, HWP 는 hwp.js 로 시도
  parse-rules.js  규칙 기반 파서
  parse-llm.js    Claude API 파서 (tool schema 로 구조 강제)
  schema.js       표준 필드 정의, 값 정규화, 검토 항목, 블라인드 처리
  render.js       표준 데이터 → A4 인쇄용 HTML
  pdf.js          HTML → PDF (Playwright)
  cli.js          배치 처리, 요약표
web/index.html    업로드 화면 (서버용)
web/demo-ui.html  브라우저 데모 화면 틀
web/build-demo.js 데모 한 장으로 묶는 빌드 (--artifact 로 조각만 출력)
samples/          서로 다른 양식의 가상 이력서 4종 + 생성 스크립트
```

## 샘플로 확인하기

```bash
node samples/make-samples.js          # 라벨형 txt, 표형 docx, 2단 pdf, 기간표 pdf, 한글 hwpx
node src/cli.js samples -o /tmp/시안 --blind
```

샘플은 전부 지어낸 가상 인물이다. 실제 지원자 자료가 아니다.
